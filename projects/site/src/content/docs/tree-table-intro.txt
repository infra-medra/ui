TreeTable applies DataTable's own column model — the same `<med-table-column field="..." header="...">` content children, unchanged — to hierarchical rows instead of a flat list. Each row of `value` is a `TreeTableNode<T>`, `{ data: T, children?: TreeTableNode<T>[], expanded?: boolean }`, so the actual record lives under `.data` and columns read `field` off that, not off the node itself. Internally the tree is flattened into one ordered list of visible rows — only descending into a node's `children` when it's expanded — and rendered as a single flat `<tbody>`, since an HTML `<tr>` can't nest another `<tr>` the way a recursive component tree can nest itself. The first column always carries the depth-based indent and the expand/collapse toggle; every other column renders exactly like DataTable's. `expanded` on a node only sets its *initial* state — toggling later is internal component state, not something you read back — and this first version deliberately has no sorting, filtering, pagination, or row selection, since none of those has one obviously correct meaning once rows have a hierarchy.
