Tree renders `value`, a flat `readonly TreeNode[]` of root entries, as a vertically indented hierarchy — a tree commonly has several top-level roots (multiple drives, multiple top-level categories), unlike a single-root structure. Each `TreeNode` is `{ label, icon?, children?, expanded?, selectable? }`; the whole hierarchy is held in memory and rendered up front, there's no lazy-loading hook for fetching a node's children on demand. `selectionMode` is `'single'`, `'multiple'`, `'checkbox'`, or `null`: `'checkbox'` is mechanically identical to `'multiple'` — each node's membership in `selection` toggles independently — it only swaps the highlighted-row look for a checkbox glyph. A node can opt out of selection entirely with `selectable: false` while still rendering and expanding normally, which is how a purely organizational grouping node (with no real record behind it) is expressed. There's no cascading parent/child selection in this version — checking a parent node doesn't check its descendants, and a partially-selected branch has no indeterminate state — each node's selection stands on its own.
