## Component: FloatLabel

### Description
`FloatLabelComponent` (`med-float-label`) is a positioning wrapper for the classic "floats up out of the field on focus/value" label pattern — `<med-float-label><input medInputText placeholder=" " class="peer" /><label medFloatLabelText for="...">Email</label></med-float-label>`. It's pure CSS, no JS reaching into the input's live value: the label positions itself off the input's own `:placeholder-shown`/`:focus` state via Tailwind's `peer-*` variants, which is why the input needs `class="peer"` and a non-empty `placeholder` (a single space is enough) added by the consumer (`projects/medra/ui/src/lib/float-label/float-label.component.ts:9-16`).

### Variants
Not applicable — a single visual pattern (floating label), no size/severity variant inputs.

### States
| State | Visual | Behavior |
|---|---|---|
| Resting (empty, not focused) | Label positioned `top-1/2`, `scale-100`, `text-(length:--text-field-base)`, `text-surface-400` — driven by `peer-[&:placeholder-shown:not(:focus)]:*` — `float-label-text.directive.ts:31` | |
| Floating (has value, or focused) | Default (non-peer-conditioned) classes: `top-0 -translate-y-1/2 scale-75 text-xs`, background patch (`bg-surface-0`) behind the label to visually "cut" the border — `float-label-text.directive.ts:29` | |

### Accessibility
- **Role/ARIA:** None found — pure positioning wrapper/directive. The `<label for="...">`/`<input id="...">` association is standard HTML, supplied by the consumer, not generated by the component. `float-label.component.spec.ts` never asserts any `role`/`aria-*`, consistent with this being purely visual.
- **Keyboard navigation:** None found / not applicable — behavior is entirely native `<input>` focus plus CSS.
- **Screen reader:** Relies on the consumer wiring a correct `for`/`id` pair; the component provides no automatic labelling. `pointer-events-none` on the label prevents it from intercepting clicks meant for the input — spec-verified: `float-label.component.spec.ts:49-53 — 'is non-interactive (never intercepts a click meant for the input)'`.
- **CSS-trick correctness:** the "float" logic is a single compound peer selector (`peer-[&:placeholder-shown:not(:focus)]:...`), not two independently-toggled classes that could race/conflict — spec-verified: `float-label.component.spec.ts:42-47 — 'rests inside the field only when the peer is both placeholder-shown and not focused, via one compound selector (not two independently-ordered ones)'`. The default (server-rendered, no JS yet) state is the floated/shrunk state, matching a filled-or-not-yet-hydrated input — `float-label.component.spec.ts:35-40 — 'defaults to the floating (up, shrunk) state'`. Focus color change is also spec-verified: `:55-59 — 'changes color on focus'`.
- **A11y verdict:** Covered — the component correctly has no ARIA surface of its own (delegated to consumer-supplied `for`/`id`), and the CSS-only float mechanism's key correctness property (single compound selector, not two racing conditions) plus non-interactivity are directly spec-verified.

### Do's and Don'ts
| ✅ Do | ❌ Avoid |
|---|---|
| Add `class="peer"` and `placeholder=" "` (a single space) on the projected input — both are required for the CSS trick to engage | Don't omit the `placeholder` attribute entirely — `:placeholder-shown` only fires when the attribute is present, even if empty |
| Match `for`/`id` between the label and input yourself | Don't expect the label to float based on a bound value alone — it only reacts to `:placeholder-shown`/`:focus`, not JS state |
| Trust the compound peer selector to avoid a "flash" between floated/resting states (spec-verified as one selector, not two) | Don't add your own click handler to the label expecting to intercept it — `pointer-events-none` is baked in and spec-verified |
